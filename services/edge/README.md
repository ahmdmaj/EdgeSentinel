# Edge Service

This directory contains the Python-based Edge Node for the EdgeSentinel platform. The Edge Node is designed to run locally on an edge device, ingesting data, running local machine learning inference, and syncing with the cloud.

## Dependencies Overview

The `requirements.txt` file outlines the core packages that power the Edge Node. Here is a breakdown of why each exists:

### 1. `fastapi`
* **What it is:** A modern, high-performance web framework for building APIs in Python.
* **Why it exists here:** The Edge Node needs its own local API. This allows local technicians to query the node's status, or the Cloud API to ping it. Right now, it's powering the `/health` endpoint, but later it will handle more complex routing.

### 2. `uvicorn`
* **What it is:** A lightning-fast ASGI web server.
* **Why it exists here:** FastAPI is just a framework; it needs a server to actually "run" it and listen for incoming web traffic. Uvicorn is the engine that binds to port `8000` and hands the HTTP requests over to FastAPI to process.

### 3. `paho-mqtt`
* **What it is:** The official Eclipse Python client for the MQTT messaging protocol.
* **Why it exists here:** In an IoT/Edge architecture, devices don't usually send data over heavy HTTP requests; they stream telemetry via lightweight MQTT messages. The Edge Node uses this library to subscribe to our `mosquitto` broker, continuously listening for the data being generated by our `simulator`.

### 4. `scikit-learn`
* **What it is:** The industry-standard machine learning library for Python.
* **Why it exists here:** This is the brains of our "anomaly detection." Instead of sending all raw data to the cloud (which takes bandwidth and fails if the internet goes down), the Edge Node will use `scikit-learn` to run lightweight ML models *locally* on the incoming MQTT data to detect anomalies in real-time.

### 5. `sqlalchemy`
* **What it is:** A powerful Database toolkit and Object-Relational Mapper (ORM) for Python.
* **Why it exists here:** Because EdgeSentinel is **"offline-first."** If the Edge Node loses connection to the Cloud API, it can't just lose the data. It will use SQLAlchemy to easily save the incoming telemetry and anomaly alerts to a local SQLite database file. Once the internet returns, it will sync that saved data to the cloud.

---

### Data Flow (Milestone 1 Preview)
The `simulator` sends data -> `paho-mqtt` receives it -> `scikit-learn` analyzes it for anomalies -> `sqlalchemy` saves it locally -> `fastapi`/`uvicorn` serves it up!
